=== Proof of Concept (PoC) Applikation
Der Chatbot sowie der MCP-Server sind eigenständige Services, die über die streamable HTTP-Schnittstelle kommunizieren. Beide sind als Docker-Container konstruiert und mittels Docker Compose orchestriert. Als Programmiersprache wird Python eingesetzt. Das Python-Ökosystem für künstliche Intelligenz ist sehr ausgereift und wird aktiv weiterentwickelt cite:[nguyen_machine_2019]. Ausserdem bietet es sämtliche Software Development Kits (SDK), die vonnöten sind. Für die Applikation wird Python genutzt, die schnelle Verfügbarkeit von KI-SDKs und die etablierte Toolchain begründen die Wahl hinreichend.

==== MCP Server

Der MCP-Server v2 stellt ein Werkzeug (`Tool`) und eine Ressource (`Resource`) bereit:

* **Tool: `abfrage_jahresbericht`**: Strukturierte Datenabfrage mit Filterung nach Jahr, Region, Zeitschiene, Kenngrösse und Sender. Unterstützt Pivot-Tabellen und Sortierung. Gibt Markdown-Tabellen zurück.

* **Ressource: `glossar`**: Glossar mit Fachbegriffen der TV-Forschung (Marktanteil, Rating, Nettoreichweite, Sehdauer, etc.).

===== Datenverarbeitung

Das `abfrage_jahresbericht` Werkzeug nutzt pandas für die Datenverarbeitung:

1. **Filterung**: Die Parquet-Datei wird als pandas DataFrame geladen. Filter werden direkt auf den DataFrame angewendet (z.B. `df[df["Jahr"].isin([2019,2020,2021])]`).

2. **Pivot-Tabellen**: Bei Vergleichen über mehrere Dimensionen (z.B. mehrere Jahre oder Sender) werden Pivot-Tabellen erstellt (`pivot_table` mit `index` und `columns`).

3. **Sortierung**: Ergebnisse können nach beliebigen Spalten aufsteigend oder absteigend sortiert werden (`sort_values`).

4. **Ausgabe**: Das Ergebnis wird als Markdown-Tabelle formatiert und zurückgegeben (`to_markdown`).

Die Glossar-Ressource wird als statischer Markdown-Text bereitgestellt und enthält Definitionen für alle wichtigen Kennzahlen der TV-Forschung.

==== MCP Client (Chatbot)
Der Chatbot implementiert einen agentenbasierten Verarbeitungsloop mit dem `gpt-4o-mini` cite:[llmGpt4oMini] sowie `gpt-5-mini` cite:[llmGpt5Mini] Model von OpenAI. Um aufwendiges Sessionhandling zu verhindern und die Komplexität zu reduzieren, wird pro Nachricht eine neue MCP-Session genutzt. Dies hat den Vorteil, dass der Kontext zeit- und serverunabhängig ist. Der Kontext ist immer gültig, auch bei Abbrüchen der Verbindung. Bei zwischenzeitlichen Serveraktualisierungen können zukünftige Nachrichten von potenziell neuen Tools oder Funktionen profitieren. Der Agent kann bis zu 15 Tool-Runden durchlaufen, bevor er eine finale Antwort produziert. Beim Erreichen der maximalen Runden wird abgebrochen um Endlosschleifen zu verhindern.

==== System Prompt (OpenAI Agent)
Damit der OpenAI Agent funktionieren kann, wird dem Agenten zusätzlich zu den Benutzereingaben und Antworten vom Large-Language-Model (LLM) eine vordefinierte Instruktion (System Prompt) mitgegeben. Die System Prompt gibt dem LLM definierte Anweisungen, wie die Tools genutzt oder die Antworten formuliert werden sollen. Da von deutschen Eingaben ausgegangen wird, wird sie auf Deutsch definiert. Der System Prompt wird eine Identität verliehen und ein Ablauf definiert. Als Identität wird die Rolle «Datenassistent für die Analyse» definiert. Der Ablauf hat einen «Abfragen» und einen «Antworten» Bereich. *Abfragen:* Als erstes wird beschrieben, dass das `abfrage_jahresbericht`-Tool aufgerufen wird, sowie wie mit dem Tool umgegangen wird. Über Standardwerte wird informiert, Spalten beschrieben sowie die Sortierung bestimmt. *Antworten:* Der Antworten Abschnitt erhält Instruktionen über Formulierungen bei Antworten mit und ohne Daten.

Die vollständige System Prompt kann im GitHub Repository cite:[githubRepoTransferarbeit] unter `poc/apps/chatbot/src/chatbot/system_prompt_v2_minimum.py` nachgelesen werden.

==== Diskussion
Für Produktionssysteme mit vielen simultanen Anfragen wäre der MCP-Server in einer Sprache wie Go oder Rust performanter. Da jedoch der Flaschenhals bei der LLM-Verarbeitungszeit liegt und nicht bei der Datenabfrage, ist die Wahl von Python für den Proof-of-Concept gerechtfertigt. Die Applikation dient primär der Validierung des Konzepts, nicht der Produktionsreife. Die Anzahl der maximal 15 Tool-Runden wurde bei keiner einzigen Frage erreicht. Für ein produktives System muss dies genauer analysiert werden.
