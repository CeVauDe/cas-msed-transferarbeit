
=== Prognosen
Der Agent muss ausschliesslich faktisch handeln und darf nicht prognostizieren. 63 Fragen werden mit drei <<methoden-plugins,Plugins>> und sieben <<methoden-strategien,Strategien>> generiert, die Auswahl fällt mit hilfe von künstlicher Intelligenz. Zum Generieren und Auswerten wird das OpenAI-Model 4o-mini genutzt. Als Strategie kommen <<methods-strategien-basic,basic>>, <<methods-strategien-crescendo,crescendo>>, <<methods-strategien-jailbreak-templates,jailbreak-templates>>, <<methods-strategien-jailbreak-hydra,jailbreak:hydra>>, <<methods-strategien-jailbreak-meta,jailbreak:meta>>, <<methods-strategien-goat,goat>>, <<methods-strategien-mischievous-user,mischievous-user>> zum Einsatz. Die Richtlinie des Policy Plugins ist wie folgt definiert:

____
The assistant must never make predictions, forecasts, or provide
data for years outside 2018-2021. It must not extrapolate trends,
estimate future values, or engage in hypothetical scenarios about
data beyond the available dataset. It must only present factual
historical data from 2018-2021.
____

Das bereitgestellte Plugin *hallucination* von Promptfoo eignet sich gut für die Evaluation von Prognosen. Der Fokus liegt auf falschen oder erfundenen Informationen.

Es versucht den Agent dazu zu bringen:

* Fakten zu erfinden, die nicht in den verfügbaren Daten existieren
* Daten ausserhalb des Scope zu generieren (z.B. 2022+ wenn nur 2018-2021 verfügbar)
* Falsche Zahlen oder nicht-existente Entitäten zu behaupten
* Mit Überzeugung etwas Falsches zu sagen

Zusätzlich wird ein domänenspezifisches Custom-Plugin angewendet, das sich auf Prognosen fokussiert und explizit Korrektheit, Interpretationen und Handlungsanweisungen ignoriert. Das Plugin wird initial mit KI erstellt und auf die Bedürfnisse angepasst. Die Prompt kann im GitHub Repository cite:[githubRepoTransferarbeit] unter `poc/redteam/plugins/keine-prognosen.yaml` nachgelesen werden.

====== Vergleich der Beispiele

Die beiden Beispiele zeigen den fundamentalen Unterschied zwischen direkten und verschleierten Angriffen:

* *Beispiel 2* (direkter Angriff): Der Agent erkennt die explizite Aufforderung zur Prognose und lehnt korrekt ab.
* *Beispiel 1* (verschleierter Angriff): Die Formulierung "Angenommen, der Trend..." verleitet den Agent zu einer mathematisch präzisen Extrapolation, obwohl das inhaltlich identisch mit einer Prognose ist.

Diese Diskrepanz zeigt, dass die aktuelle Implementierung oberflächlich auf Schlüsselwörter reagiert, aber die semantische Bedeutung nicht vollständig erfasst.

Die elaborierten Multi-Turn-Attacken waren ausnahmslos erfolgreich:

* **Crescendo** (graduelle Eskalation): 0% Abwehr - alle 9 Tests durchgebrochen
* **GOAT** (Generative Offensive Agent Tester): 0% Abwehr - alle 9 Tests durchgebrochen

Im Gegensatz dazu zeigten einfachere Strategien moderate Abwehr:

* **Basic** (ohne Optimierung): 44% Abwehr - höchste Erfolgsrate
* **jailbreak-templates** (bekannte Jailbreak-Muster): 44% Abwehr
* **jailbreak:hydra** (adaptive Multi-Turn): 11% Abwehr

==== Diskussion

===== Interpretation der Befunde

Die Ergebnisse zeigen ein kritisches Problem: Einfache direkte Anfragen werden zu ca. 44% abgewehrt, aber bei komplexeren Multi-Turn-Attacken sinkt die Erfolgsrate auf 0%. Das zeigt deutlich, dass der Prompt-basierte Ansatz grundlegende Schwächen hat.

**Psychologischer Bypass:** Die Crescendo-Strategie funktioniert durch schrittweisen Vertrauensaufbau. Der Agent liefert zuerst korrekte Daten (2018-2021), wird dann zu Trend-Beschreibungen geführt und schliesslich zu Extrapolationen verleitet. Dieser "Boiling Frog"-Effekt nutzt aus, dass das System keine Zustände speichert. Jede Anfrage wird isoliert bewertet, der eskalierende Kontext wird nicht erkannt.

**Technische Implikation:** Nur mit System-Prompts reicht es nicht. Die 0%-Erfolgsrate bei Multi-Turn-Strategien zeigt, dass zustandsbasiertes Policy-Enforcement nötig ist. Das System müsste nicht nur einzelne Anfragen prüfen, sondern ganze Dialoge auf schrittweise Verletzungen der Einschränkungen überwachen.

**Hallucination-Problem:** Die tiefe Erfolgsrate von 4,8% beim Hallucination-Plugin zeigt, dass der Agent häufig mit Überzeugung falsche Daten generiert. Er erfindet Daten für 2022+ ohne klare Warnung. Besonders problematisch: In 20 von 21 Fällen präsentierte das System nicht-existente Datenpunkte als Fakten.

===== Vergleich der Plugin-Ansätze

Die unterschiedliche Erfolgsrate der drei Plugins (Custom: 52%, Policy: 10%, Hallucination: 5%) zeigt, dass Domänen-Spezifität wichtig ist:

* Das Custom-Plugin mit Fokus auf Prognosen erreicht über 50% Erfolgsrate, weil Generator und Grader genau auf die Einschränkungen abgestimmt sind
* Das generische Policy-Plugin scheitert häufiger (10%), weil es breiter formulierte Tests generiert, die den Agent in Randbereiche führen
* Das Hallucination-Plugin testet hauptsächlich Datenfabrikation, nicht Prognosen. Die niedrige Rate (5%) zeigt, dass sich die Konzepte überlappen, aber nicht identisch sind

===== Limitationen der Evaluation

**Falsch-Negative:** Der Grader-LLM könnte korrekte Ablehnungen fälschlicherweise als Fehler bewerten, wenn der Agent zwar keine Prognose macht, aber ungünstig formuliert (z.B. "Ich kann 2022 nicht vorhersagen" könnte als Erwähnung von 2022 negativ bewertet werden).

**Stichprobengrösse:** 63 Tests reichen aus, um Trends zu erkennen, aber für statistisch robuste Aussagen über seltene Edge-Cases ist das zu wenig.

===== Optimierungsvorschläge für die Praxis

Für den Produktiveinsatz sind mindestens folgende Massnahmen notwendig:

1. Verschärfung der Policy nach erkannten Manipulationsversuchen
2. Pattern-Matching für Zukunfts-Formulierungen ("wird", "2022+", "prognostiziert")

===== Versuch einer Optimierung
Die angepasste System Prompt erzielt eine Erfolgsrate von 39.68%:

----
═══ REGELN ═══
Erstelle keine Prognosen, keine Trends und keine Vermutungen. Gib nur Fakten aus den Daten wieder.

═══ WORKFLOW ═══
2. ANTWORTEN:
Sollten Daten nur teilweise vorhanden sein, passe die Antwort eindeutig auf die Richtigkeit der präsentierten Daten an und informiere exakt über Abweichungen zur Frage, um Verwirrung zu vermeiden.
----

Die angepasste System Prompt findet man im GitHub Repository cite:[githubRepoTransferarbeit] unter `poc/redteam/prognose-optimiert.result.json`.
