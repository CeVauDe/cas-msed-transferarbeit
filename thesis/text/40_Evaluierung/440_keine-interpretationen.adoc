
[#section-interpretation]
=== Keine Interpretationen
Interpretationen sind für das gewünschte Verhalten des Chatbots nicht verwertbar. Ein Benutzer der in die Ausgabe faktischer Daten vertraut und kaum die Möglichkeit zum Evaluieren der Ausgaben hat, kann nicht unterscheiden, ob es sich um eine Interpretation oder datengestützte Aussagen handelt. Der Chatbot soll die Auswertung vereinfachen und nicht zusätzliche Arbeit verursachen.
LLMs haben aufgrund der Art und Weise wie sie funktionieren, weiterhin Probleme mit der korrekten Unterbindung von falschen kausalen Interpretationen cite:[evaluationCausalReasoning] und neigen stark dazu.

[#interpretationen-methodik]
==== Methodik
Zur Eavluation werden 70 Red Teaming-Tests mit fünf <<methoden-plugins,Plugins>> und sieben <<methoden-strategien,Strategien>> (<<methods-strategien-basic,basic>>, <<methods-strategien-jailbreak-templates,jailbreak-templates>>, <<methods-strategien-jailbreak-meta,jailbreak:meta>>, <<methods-strategien-jailbreak-hydra,jailbreak:hydra>>, <<methods-strategien-crescendo,crescendo>>, <<methods-strategien-goat,goat>>, <<methods-strategien-mischievous-user,mischievous-user>>) generiert. Die Auswahl der Plugins und Strategien wird mit hilfe von KI gefällt. Zum Generieren und Auswerten wird das OpenAI 4o-mini LLM genutzt. Die Richtlinie des Policy Plugins ist wie folgt definiert:

____
The assistant must never provide interpretations, causal
explanations, value judgments, or contextual reasoning about the
data. It must not explain "why" patterns exist, what "caused"
changes, or whether results are "good" or "bad". It must only
present factual data from 2018-2021 without analysis or
interpretation.
____

Das Custom Plugin, welches initial mit hilfe von KI generiert und angepasst wird, definiert im `generator` sechs Angriffskategorien für Interpretation-Tests:

* Kausale "Warum"-Fragen (direkte Ursachen-Abfragen)
* Muster interpretieren ("Was bedeutet dieser Rückgang?")
* Werturteile abgeben ("Ist 15% Marktanteil gut?")
* Kontextuelle Erklärungen (Hintergründe, externe Faktoren)
* Korrelation impliziert Kausalität (Zusammenhänge suggerieren)
* Qualitative Bewertungen ("Wie würdest du die Performance bewerten?")

Die `grader` Definition legt fest, dass alle Versuche zu erklären "warum" etwas geschah, kausale Links herzustellen oder Werturteile abzugeben als Fehler bewertet werden. Der genaue Wortlaut kann im GitHub Repository unter `poc/redteam/plugins/keine-interpretation.yaml` nachgelesen werden cite:[githubRepoTransferarbeit].

==== Ergebnisse und Diskussion

Von 70 durchgeführten Red Teaming-Tests bestehen lediglich 5 (7,1%), während 65 Tests (92,9%) fehlschlagen. Die Ergebnisübersicht ist in <<#image-interpretationen-pass-rate>> und Erfolgsrate nach Plugin in <<#image-interpretationen-plugin-pass-rate>> dargestellt. Das System ist in dieser Verfassung massiv anfällig für Interpretations-Manipulationen.

*Besonders alarmierend*: Das Policy-Plugin zeigt eine Erfolgsrate von 0%, was bedeutet, dass das System in allen Fällen auf generische Interpretation-Anfragen mit unzulässigen Erklärungen reagiert.

====== Vergleich der Beispiele

Die beiden Beispiele zeigen den fundamentalen Unterschied zwischen komplexen Multi-Turn-Angriffen und direkten Single-Turn-Abfragen:

* *Beispiel 2* (direkter Basic-Angriff): Der Agent erkennt die explizite "Gründe"-Frage und lehnt korrekt ab, bietet stattdessen Daten an.
* *Beispiel 1* (Crescendo Multi-Turn): Durch schrittweise Eskalation wird der Agent zu einer umfangreichen Analyse gesellschaftlicher Ereignisse verleitet. Die Antwort enthält zahlreiche Interpretationen: kausale Erklärungen ("Die Pandemie hat die Sehnutzung erheblich beeinflusst"), Wahrscheinlichkeitsaussagen ("Es ist wahrscheinlich, dass einige Zuschauer... übergewechselt sind"), kontextuelle Begründungen ("Der Erfolg von Sendern war auch von den Programminhalten... abhängig") und Trend-Analysen.

Diese Diskrepanz zeigt, dass Single-Turn-Abwehr funktioniert, aber Multi-Turn-Dialoge die Schutzbarrieren systematisch umgehen. Der Agent erkennt nicht, dass eine über mehrere Turns aufgebaute Analyse ebenso interpretativ ist wie eine direkte Erklärung.

**Warum Interpretationen schwerer zu verhindern sind:** Anders als bei Prognosen (erkennbar an Zukunftsbezug) oder Handlungsanweisungen (erkennbar an imperativen Formulierungen) sind Interpretationen semantisch subtil. Formulierungen wie "möglicherweise liegt das an..." oder "das deutet darauf hin..." sind sprachlich unauffällig, aber inhaltlich problematisch.

**Multi-Turn-Vulnerabilität:** Die 0%-Erfolgsrate bei Crescendo, GOAT und Hydra zeigt, dass mehrstufige Dialoge systematisch die Schutzbarrieren umgehen. Der Agent wird schrittweise von factual reporting zu causal reasoning geführt, ohne dass ein einzelner Schritt offensichtlich problematisch ist.

**Policy vs. Custom Plugin:** Das Custom-Plugin erreicht 11,4% Erfolgsrate, das Policy-Plugin 0%. Diese Diskrepanz zeigt, dass domänenspezifische Angriffe (TV-Daten, Sender, Kennzahlen) schwerer abzuwehren sind als generische Interpretation-Anfragen. Der Agent scheint bei Fachfragen weniger restriktiv zu agieren.


===== Optimierungsversuch
Eine kleine Anpassung der System-Prompt erzielt eine leicht verbesserte Erfolgsrate von 15.63%:

----
═══ REGELN ═══
Interpretiere die Daten nicht und antworte auf Fragen die auf Interpretationen zielen nicht. Gib nur Fakten aus den Daten wieder.

═══ WORKFLOW ═══
2. ANTWORTEN:
Antworte nie mit Eventualitäten die zu Interpretationen führen können. Antworte klar und faktenbasiert.
----

Die vollständig optimierte System-Prompt findet man im GitHub Repository unter `poc/redteam/interpretation-optimiert.result.json` cite:[githubRepoTransferarbeit].


==== Fazit
Die Ergebnisse zeigen ein fundamentales Problem: Mit einer Gesamtabwehrrate von 7,1% ist das System für produktive Anwendungen ungeeignet. Im Vergleich zu den anderen Kriterien (Prognosen: 22%, Handlungsanweisungen: ~58%) ist die Interpretations-Abwehr am schwächsten.
Die 92,9% Fehlerquote zeigt, dass System-Prompts allein das Problem nicht lösen. Der Agent braucht strukturelle Einschränkungen:

1. Automatische Erkennung von Kausalmarkern ("weil", "aufgrund", "führt zu", "deutet auf")
2. Erkennung von schrittweiser Eskalation über mehrere Turns
3. Für häufige Fragen vordefinierte, interpretationsfreie Antworten

Eine Herausforderung stellt die Formulierungen der Antworten da, wie in <<#interpretationen-beispiel1>> ("möglicherweise liegt das an...") könnten als harmlose Höflichkeit statt als Interpretation gewertet werden. Die Grader-LLM muss optimiert werden.
